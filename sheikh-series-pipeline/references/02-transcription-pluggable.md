# ٠٢ — التفريغ التبادلي (Pluggable Transcription) — عقد المخرجات، بوابة الجودة، وإدارة الكوتة

## البنية العامة: طبقة تفريغ قابلة للتبديل (Pluggable Transcription Layer)

تعتمد المهارة طبقة تفريغ عامة محكومة بـ**عقد مخرجات معياري** و**بوابة جودة صارمة**، مما يتيح استبدال أو ترقية نماذج التفريغ دون المساس بالمراحل اللاحقة للخط.

- **النموذج الافتراضي الموصى به:**
  ```python
  DEFAULT_MODEL = "gemini-3.8-flash-high"
  ```
- **قابلية التبديل والتهيئة:**
  يُمرَّر النموذج عبر متغير البيئة `$TRANSCRIBE_MODEL` أو عبر معامل سطر الأوامر `--model`.
- **أداة التنفيذ المثبتة:** `agy` عبر سكربت التفريغ الموحّد:
  ```bash
  python3 ${SERIES_WORKSPACE}/mirath-tools/agy_transcribe.py <audio.mp3> <out.txt> --model "${TRANSCRIBE_MODEL:-gemini-3.8-flash-high}"
  ```

## ١) عقد المخرجات المعياري (Output Contract)

كل درس يُفرَّغ يجب أن يُسلِّم مخرجين قياسيين في مخزن العمل `ytb/<sheikh>/<row>/`:

1. **ملف النص الصافي (`<NNN>_<VID>.txt`):**
   - نص عربي كامل وحرفي للمادة المنطوقة، مع علامات الترقيم وفواصل الفقرات الطبيعية.
   - سلامة تامة للآيات القرآنية ورسمها ونصوص الاقتباس.
   - خلو كامل من أي حوار وهمي أو تلخيص أو تكرار أو تعليق وصفي للمهمة.
2. **سجل البيانات الوصفية (`<NNN>_<VID>.meta.json`):**
   - يحمل التوثيق التقني لعملية التفريغ وفق المخطط:
     ```json
     {
       "chars": 48250,
       "model": "gemini-3.8-flash-high",
       "ok": true,
       "when": "2026-10-15T00:30:00Z",
       "declared_total": 15,
       "row_keys": ["539"]
     }
     ```
   - **قاعدة التعديل:** مفاتيح `meta.json` تُضاف وتُحدَّث ولا تُحذف أبداً.

### تعريف التفريغ الصالح (Valid Transcript):
```python
def valid_transcript(p):
    if not os.path.exists(p) or os.path.getsize(p) < 1200:
        return False
    content = open(p, "rb").read()
    return b"blocked by Gemini" not in content and b"This request was blocked" not in content
```
*سبب عتبة ١٢٠٠ بايت:* رسائل الحجب والأخطاء والملفات المبتورة أقصر من أي مادة علمية حقيقية؛ وهذه العتبة تمنع اعتبار ملف معطوب «منجَزاً» بصمت.

## ٢) بوابة الجودة والتنظيف (Quality Gate & Sanitization)

لا يُعتمد أي ملف ولا يُمرَّر إلى خط المحاذاة إلا بعد اجتياز فحص بوابة الجودة الصارم:

### أ) بوابة التحقق الآلي (`check_transcripts.py`):
يكتشف العيوب التالية ويُرجع كود خروج `exit 1` عند وجود أي عيب:
- `LATIN_PREAMBLE`: تسريب سرد أو توجيهات إنجليزية في بداية النص ناتجة عن جلسات الوكلاء (مثل `"I have launched the transcription..."` أو `"No tools called..."`).
- `EMPTY`: ملف خالٍ من الحروف العربية.
- `SHORT`: تفريغ قصير شاذ (< ٤٠٠ حرف عربي للمحاضرة الكاملة).
- `META_MISMATCH`: عدم تطابق عدد المحارف المسجل في `meta.json` مع الطول الحقيقي للملف.

### ب) أداة التنظيف والأرشفة (`sanitize_preamble.py --apply`):
- يقطع أي مقدمات أو سرد لاتيني قبل أول حرف عربي صريح.
- **الأرشفة الحتمية (لا حذف نهائي):** يُؤرشف الملف الأصلي في المجلد `<root>/_fix/english-preamble/`، ويُحدّث السجل بـ `chars/sha256/cleaned`.

## ٣) الدليل التجريبي لتبرير النموذج الافتراضي (`flash-high` مقابل `argon`)

لا يتم اختيار النموذج الافتراضي عشوائياً، بل استناداً إلى قياسات تجريبية موثقة على نفس كاش ASR لبيان الكلفة والجودة:

| المقياس التجريبي (على نفس كاش ASR) | gemini-3.8-flash-high (الافتراضي الموصى به) | gemini-4-argon-high (تجريبي) |
|---|---|---|
| نسبة المراسي التامة في المحاذاة | ٤٥٫٣٪ | ٤٦٫٦٪ (**فارق هامشي: +١٫٣ نقطة فقط**) |
| تكلفة استهلاك الكوتة (محاضرة ٢٧د) | ≈ ٠٫١٠٦ نقطة | **≈ ٠٫٦٩ نقطة (تكلفة ٦٫٥ أضعاف)** |
| الزمن المستغرق لكل دقيقة صوت | ≈ ٢٫٢ ثانية | **≈ ٧٫٦ ثانية (أبطأ ٣٫٥ أضعاف)** |
| التشكيل الصوتي في الآيات القرآنية | ١١٫٥٪ – ١٥٫٩٪ من الكلمات | **٠٫٢٪ – ٠٫٤٪ (أسقط علامات التشكيل)** |
| علامتا الآيات ﴿﴾ | محفوظة ومنضبطة | **مفقودة في بعض الدروس** |

**الخلاصة المرجعية:** نموذج `flash-high` يقدّم التوازن الأمثل بين السرعة والتكلفة البسيطة والحفاظ على تشكيل الآيات القرآنية، بينما القيد الفعلي على دقة المحاذاة يكمن في كاش ASR وخوارزمية المراسي (v2/v3) وليس في تفريغ النص نفسه.

## ٤) ميكانيكا الاستدعاء الآمن عبر `agy`

1. **المرفق الصوتي (`@file`):**
   - يُمرَّر الصوت حصراً بصيغة مرفق `@<basename>.mp3` في صدر البرومبت.
   - ذكر مسار الملف نصياً داخل سياق الجملة يؤدي إلى حجب الطلب (`blocked by Gemini's filters`).
   - يجب أن يكون مجلد العمل (`workdir`) محتوياً على الملف الصوتي بنفس الاسم تماماً.
2. **صلاحيات الأداة:**
   - استدعاء المرفق يتطلب تمرير `--dangerously-skip-permissions` لتفادي رد `denied_actions:[{"action":"command"}]`.
3. **البرومبت الحرفي المعتمد:**
   ```
   @<name> هذا تسجيل صوتي لمحاضرة علمية عربية. اكتب التفريغ النصي الكامل والحرفي بالعربية
   مع علامات الترقيم وفواصل الفقرات. أخرج النص فقط بلا أي تعليق أو مقدمة أو خاتمة.
   لا تلخّص، ولا تعيد أي جملة مرتين، ولا تكتب حواراً وهمياً.
   إذا لم تستطع إكمال الملف كاملاً فأكمل ما استطعت ثم اكتب في آخر سطر: [ناقص].
   ```

## ٥) إدارة الكوتة ومراقبة النطاق

- **أمر الفحص المباشر:**
  ```bash
  agy -p "/usage" --output-format json
  ```
- **هيكل البيانات والحساب الآمن:**
  يجب تسطيح البنية التكرارية `groups[].buckets[]` واستخراج نسبتي `gemini-5h` و `weekly`.
  * تحذير قاطع: إذا رجع القاموس فارغاً، يُعتبر النطاق مجهولاً ويُوقف التوسع، ولا يُفترض أنه ١٠٠٪.
  * شرط التوقف التلقائي: `gemini-5h < min_five_hour` أو `weekly < 2.0%`.
- **معدل الاستهلاك المقيس:**
  * درس مدته ~٢٧ دقيقة يستهلك ≈ ٠٫١٠ نقطة أسبوعية.
  * احسب دائماً المتبقي: `(النسبة المتبقية - حد الأمان) / 0.10` لمعرفة عدد الدروس الممكن إنجازها قبل بدء الدفعة.

## ٦) التوازي وحارس الفشل

- **إدارة الموارد على الخادم:** الخادم بـ ٤ أنوية و~٧٫٨GB RAM بلا swap يتحمل **٢–٣ عمّال agy متوازيين** كحد أقصى.
- **منع قتل العمّال:** لا تقتل عاملاً جارياً لتفريغ مكان لعامل آخر؛ لأن كوتة الطلب تُحسب فور بدئه، وإلغاؤه يعني حرق الكوتة وفقد التفريغ.
- **حارس الفشل التلقائي (`failed_watch.py` يعمل كل ١٥ دقيقة):**
  1. يمسح سجلات الحالة بحثاً عن الحالات المعلّمة بـ `failed`.
  2. يتحقق إن كان التفريغ قد كُتب في أي مخزن فيلغي حالة الفشل.
  3. إن لم يتوفر، يعيد تنزيل الصوت ثم يعيد طلب التفريغ عبر الخط المعتمد.
  4. يرصد التوقف غير الطبيعي: أي قائمة جارية بلا كتابة ملفات منذ أكثر من ٩٠ دقيقة.
